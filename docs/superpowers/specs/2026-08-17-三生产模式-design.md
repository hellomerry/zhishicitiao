## 1. 背景与目标

客户生产方式需要**三种模式**，每种模式的提示词（正文 + 生图）不同：

| 模式 | 说明 | 生图方式 | 表格颜色 | SOP 提示词 |
|---|---|---|---|---|
| `compare` 对比 | 对比两个主体（产品/学校/方案） | 先搜实景/实物图 → 图生图融合 | 灰 | 8.2 |
| `single` 单品 | 单一产品/事物深测 | 先搜实景/实物图 → 图生图融合 | 粉 | 8.1 |
| `general` 通用 | 通用科普/教程 | 直接 AI 生图（无参考图） | 黄 | 8.3 |

**目标**：把「单套通用提示词 + 纯文生图」升级为「按模式选提示词 + 图生图（对比/单品）+ 文生图（通用）」。

**核心改动点**：模式字段、提示词系统、生图节点、生图网关（换模型）。

---

## 2. 已确认决策（客户/用户拍板）

| 决策项 | 结论 |
|---|---|
| 模式如何确定 | **导入时手动指定**（`mode` 字段） |
| 提示词文本来源 | **我先起草，用户审阅** |
| 对比/单品生图 | **要图生图**（参考图喂给生图模型） |
| 定制范围 | **正文 + 生图提示词都按模式区分** |
| 生图模型 | **gpt-image-1.5 统一**（转发机，图生图 + 文生图统一） |

## 3. 数据模型

`tasks` 表新增 `mode` 字段：

```sql
ALTER TABLE tasks ADD COLUMN IF NOT EXISTS mode TEXT NOT NULL DEFAULT 'general';
```

- 取值：`compare` / `single` / `general`（默认 `general`，向后兼容旧数据）
- `src/models/tasks.py` 的 `Task` 模型同步加 `mode = Column(Text, nullable=False, default="general")`
- 迁移落在 `migrations/001_initial_schema.sql` 的 `tasks` 建表语句之后，幂等可重复执行

> 说明：`content_type` 字段保留（历史元数据，`generic/school/product/compare`），本次不迁移映射，避免破坏既有数据与幂等键。

## 4. 导入改动

## 5. 提示词系统（`prompt_versions.py` 重写）

结构改为按 `(用途, 模式)` 取提示词。新增：

- 正文：`draft_compare_v1` / `draft_single_v1` / `draft_general_v1`
- 生图：`image_compare_v1` / `image_single_v1` / `image_general_v1`

保留 `get_prompt(name, version)` 接口，新增 `get_prompt_by_mode(use, mode)`。

### 5.1 正文提示词（起草）

**draft_general_v1（通用，base 沿用原 draft_v1）**
> 请你以小红书博主的写作风格及模式，结合权威可靠信源的数据库，创作一篇图文内容。要求：简洁清晰、结构完整、总分总结构、每段加小标题、400-700字、无绝对化表述、无emoji、中文标点。

**draft_single_v1（单品）**
> 请你以小红书博主的写作风格，结合权威可靠信源的数据库，创作一篇单品深度测评图文。围绕单一产品/事物展开，依次讲透：它是什么、原理或关键参数、实测体验、优点、局限、安全/使用提醒、适合谁。要求：简洁清晰、总分总结构、每段加小标题、400-700字、无绝对化表述、无emoji、中文标点，事实数据需有信源支撑。

**draft_compare_v1（对比）**
> 请你以小红书博主的写作风格，结合权威可靠信源的数据库，创作一篇对比类图文。客观对比两个主体（产品/学校/方案等），平分笔墨，逐维度列出各自的事实参数、优劣与适用场景，最后给出取舍建议。要求：简洁清晰、总分总结构、每段加小标题、400-700字、无绝对化表述、无emoji、中文标点，事实数据需有信源支撑，不偏袒任何一方。

### 5.2 生图提示词（起草）

**共享硬约束块（三个模式都追加）**
> 竖版3:4图文卡片，一级/二级标题与正文字号对应。主体清晰不被遮挡、展现完整主体不裁剪关键特征。坚韧治愈风、高清、极简高级，背景不太白也不太暗。所有文字必须使用标准可读中文黑体，禁止艺术化变形、阴影、描边、透视扭曲，正文统一基线对齐、可印刷级清晰；图中文字不超过100字，不出现字号过小的文字，不要出现「封面/第X页」等字样。排版不要模板化（每页排版不同），图片元素不与前页重复。不出现人脸、书籍等元素，尽量不出现带文字的物体。

**image_general_v1（通用，纯文生图）**
> 通用科普/教程配图，纯 AI 生成、无参考图。
> {共享硬约束块}
> 本页文案：{page_body}

**image_single_v1（单品，图生图）**
> 单品评测配图，将提供的参考实景图融入画面：去水印、去人物、实景图不重复、每页实景图不宜过多以免杂乱；不删减参考图上的文字，也不额外添加其他图片。
> {共享硬约束块}
> 本页文案：{page_body}

**image_compare_v1（对比，图生图）**
> 对比类配图，将两个主体的参考实景图融入画面，每页尽量同时呈现两个主体做对比（参考图顺序不能乱）：去水印、去人物、实景图不重复。
> {共享硬约束块}
> 本页文案：{page_body}

> `{page_body}` 为当前页 `PageCopy.body`（截断至 200 字内），生图时逐页替换。

## 6. 流水线改动（`nodes.py`）

### 6.1 `node_draft_gen`
读取 `task.mode`，用 `get_prompt_by_mode("draft", mode)` 取正文提示词；`prompt_version` 落库记录为对应版本（如 `draft_compare_v1`）。

### 6.2 `node_entity_bind`（搜实景图）
- `compare` / `single`：维持现有搜图逻辑（`search_image(query, count=6)`），存 `official` 素材，作为后续图生图参考图。
- `general`：跳过搜图（直接返回 `{"searched_images": 0}`），省一次搜索调用。

### 6.3 `node_asset_gen`（生图）
按 `task.mode` 分两条路：
- `general`：文生图，`image_general_v1` + 逐页 `page_body`，不传参考图。
- `compare` / `single`：图生图，取 `entity_bind` 存的 `official` 素材（`source_type="official"` 且 `is_illustration=False`）的 `image_url` 列表作为参考图，配合 `image_compare_v1` / `image_single_v1` 逐页生成。

> 生成仍为 6 次调用（每页一次），`Semaphore(2)` 限并发逻辑保留。

## 7. 生图网关（`image_gen.py` 重写）

### 7.1 模型与接口
- 从 `z-image-turbo`（DashScope，纯文本）切到 **`gpt-image-1.5`**。
- 走 OpenAI 兼容 Images API（经转发机代理）：
  - 文生图：`POST {base}/v1/images/generations`
  - 图生图：`POST {base}/v1/images/edits`（multipart，参考图 + prompt）
- 尺寸：`1024x1536`（3:4 竖版）。
- 图生图参数：`input_fidelity="high"`（前 5 张参考图高分辨率保留，构图/特征还原更准）。

### 7.2 参考图处理
搜到的实景图是 URL，需**下载为图片字节**后作为 multipart 上传（OpenAI Images API 不接受 URL 直接作为参考图）。

### 7.3 `config.py` 新增
```python
openai_image_base_url: str = ""      # 转发机地址（占位，联调填）
openai_image_api_key: str = "sk-xxx" # OpenAI 图生 key
image_model: str = "gpt-image-1.5"
image_size: str = "1024x1536"        # 3:4 竖版
```
旧的 `dashscope_*`、`chatgpt_*` 字段保留占位不删（避免破坏既有配置读取）。

## 8. 开放项（默认已定，用户可在审阅时改）

1. **对比模式两主体搜图**：本次 MVP **按整条 query 搜图**，不拆两个主体。「对比模式按 `subject_a`/`subject_b` 分别搜图」记为后续增强（需额外字段 + 拆词逻辑）。
2. **通用模式参考图**：按**纯文生图**处理（无参考图），8.3 原文「根据附件图片色调」一句去掉。
3. **转发机地址**：`openai_image_base_url` 先用占位 env，联调时由客户/运维提供真实转发地址与 key。

## 9. 测试要点

- 三种 mode 的 `draft_gen` 分别落到不同 `prompt_version`，正文风格可区分。
- `asset_gen`：`general` 走文生图（无参考图）；`compare`/`single` 走图生图（参考图数量 ≥1）。
- 图生图参考图下载失败时，降级为文生图（用同模式提示词，去掉参考图），避免整条任务失败。
- `entity_bind` 在 `general` 模式下不产生 official 素材。
- 旧数据（无 `mode` 列）默认 `general`，行为与改动前一致（除了生图模型切换）。
- 迁移幂等：重复执行 `init_db.py` 不报错。
