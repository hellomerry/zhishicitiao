# S4 容量验证（30,000 条/月）— 运营计划

> **For agentic workers:** 本阶段无代码开发，是容量/稳定性验证清单。执行时按 checklist 逐项确认，不涉及 TDD。

**Goal:** 验证队列、限流、降级、排班、峰值能力，确认系统能稳定支撑 30,000 条/月。

**性质:** 运营/容量验证阶段。无代码 task。

**Spec:** `docs/superpowers/specs/2026-08-13-产能验证平台-design.md`

**前置条件:** S3 试运营达标。

---

## 目标

- 峰值并发压测（60 条/分钟 × 5 分钟，对应 spec §2.6）
- 注入 20% 失败率验证重试余量
- 供应商限流表现 + 故障切换演练
- 排班与替补机制验证

## 容量验证 checklist

- [ ] 峰值并发：60 条/分钟持续 5 分钟，队列与降级正常
- [ ] 失败重试：注入 20% 失败率，重试后产能仍达标
- [ ] 供应商限流：记录 429/超时频次，确认未触硬限流
- [ ] 故障切换：主备供应商切换演练（切备 + 退避重试）
- [ ] 排班替补：主审缺席时自动转交同能力成员
- [ ] 队列积压：持续观测，不单调增长
- [ ] P50/P95 节点耗时：进入稳定区间

## 关键约束（对应 spec §12.3）

容量测试必须使用接近真实的正文长度、图片数、搜索次数、模型组合和重试比例。**仅用空任务或简单文本接口达到 30 次/分钟，不能证明完整生产包达标。**

测试报告应包含：供应商限流、失败重试、队列积压、成本。

## 退出条件

- [ ] 峰值 60 条/分钟稳定
- [ ] 20% 失败注入下重试仍达标
- [ ] 供应商故障切换演练通过
- [ ] 排班替补机制可用

> 达标后进入 S5（规模化）。
